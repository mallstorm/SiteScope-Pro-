# Спецификация 38 — модульные корневые Activity

## Проблема
Один `MainActivity` одновременно управлял главной страницей, SEO, проектами, историей и устаревшими сетевыми маршрутами. Это связывало несвязанные функции общими полями состояния и усложняло жизненный цикл.

## Новая схема

```text
MainActivity
├── SeoActivity
├── IpEngineeringActivity
├── IptvActivity
├── ProjectsActivity
└── HistoryActivity

BaseSiteScopeActivity
└── общий UI и нижняя навигация
```

## Правила
1. Главная не содержит бизнес-логику аудита или истории.
2. SEO отвечает только за SEO-аудит и его результат.
3. Проекты отвечают за метаданные и маршрутизацию проекта.
4. История отвечает за чтение сохранённых результатов.
5. Данные остаются в SQLite/DataStore и не передаются большими JSON через Intent.
6. Для сохранённого SEO-аудита передаётся timestamp, после чего объект читается из локального хранилища.
7. Нижняя навигация едина и содержит только три утверждённых пункта.

## Следующий архитектурный этап
- перенос статичных оболочек экранов в XML либо Compose;
- Cursor/Paging-подобные запросы для очень больших журналов;
- выделение ViewModel/state слоя;
- замена свободных Thread на управляемые executor/lifecycle jobs.
