# Постоянные карточки устройств — этап 3, beta16

## Что появилось

«Моя сеть → Устройства» показывает постоянный каталог из обнаружения SSDP/mDNS/ONVIF, открытых TCP-сервисов и сохранённых подключений. Карточка имеет собственный случайный UUID, название, адреса, даты и список записей с происхождением. Она сохраняется после перезапуска и удаления старых исходных снимков/сканирований. Список и содержимое карточки загружаются порциями по 100 с кнопкой продолжения; это не ограничивает объём сканирования.

Карточку можно переименовать, объединить с другой или разделить, выбрав часть записей. Источник, исходный ответ, признаки оборудования и адрес каждой записи сохраняются. При объединении сохраняются прежние пользовательские имена. Повторный поиск обновляет наблюдение на прежнем месте и не отменяет ручное разделение. Сервис открывается через существующую панель протоколов. Для подключения используются актуальные данные профиля, найденного по отдельной случайной ссылке.

## Как определяется принадлежность

1. Объявленный SSDP USN UUID или ONVIF EndpointReference UUID может связать разные IP одной карточки в пределах одной определённой сети. UUID приводится к единой форме; нулевые и полностью заполненные F значения не принимаются. ONVIF разбирается как SOAP/XML с проверкой пространств имён; MessageID запроса, имена и модель не являются идентификатором устройства.
2. Если в одном поиске один UUID объявляют несколько адресов, записи помечаются неоднозначными и автоматически не объединяются. Несколько карточек, уже содержащих один UUID, также запрещают однозначное автоматическое сопоставление следующего адреса. Так сохраняется результат ручного разделения.
3. Без UUID совпадение полного сервиса (сеть, адрес, порт, протокол и путь) позволяет собрать записи разных источников. Такая карточка относится к сервису по адресу и не доказывает тождество физического оборудования. Разные порты, похожие модели, имена DNS/mDNS и сертификаты сами по себе устройства не объединяют.
4. Новый UUID на прежнем адресе не подменяет карточку другого UUID. Неоднозначные совпадения остаются отдельными. Ручное объединение доступно и для разных сетей, если пользователь знает, что это одно устройство.

UUID устройства — заявленное сетевое свойство, а не криптографическое подтверждение. Клонированный UUID, появившийся последовательно на другом адресе, может быть принят за смену IP; одновременные дубли обнаруживаются. Ручное разделение позволяет исправить такую связь.

## Область сети

При доступности системного BSSID Wi-Fi используется хеш BSSID и шлюза. При скрытом BSSID, в Ethernet, мобильной сети и VPN используется отдельный сеанс Android Network с номером загрузки и локальным идентификатором установки. Номер подсети и SSID сами по себе не являются ключом. Локальный идентификатор установки не включён в переносимую резервную копию. Без данных о сети создаётся отдельная неопределённая область.

Это консервативное сопоставление: смена точки доступа, переподключение или перезагрузка телефона при скрытом BSSID могут дать отдельные карточки. Дополнительные разрешения ради BSSID приложение не запрашивает; записи можно объединить вручную.

Обнаружение сохраняет область выбранной LAN-сети. TCP/TLS-сокеты сканера и их DNS привязаны к Network, выбранной при запуске. После исчезновения этой сети новые соединения не должны незаметно перейти на другую. Восстановление checkpoint при изменившейся или неизвестной прежней области сохраняет прежние результаты и предлагает новый запуск.

## Хранение и совместимость

- SQLite v3 добавляет `device_cards` и `device_observations` с внешним ключом и индексами. Существующие таблицы сохраняются.
- Полные записи источников хранятся независимо от лимита 20 исходных поисков и 30 сканирований. Повтор того же наблюдения обновляет последнюю запись, а не создаёт временной ряд. История изменений и политика её хранения относятся к этапу 4.
- Старые данные без сведений о сети импортируются в отдельные области каждого источника; старые названия по IP переносятся только в соответствующие прежние discovery-карточки. Автоматически приписывать их новой сети нельзя.
- Резервная копия v8 переносит UUID карточек, связи, названия и ручные назначения. До удаления данных проверяются уникальность ID и целостность ссылок. Ошибка восстановления откатывает транзакцию. Прежние копии без каталога поддерживаются: каталог восстанавливается из доступных источников при открытии экрана.
- Каталог не дублирует URI, пароль, заметки или старый ID сохранённого подключения, который мог содержать URI. Используется отдельный `deviceRef`. Общая очистка секретов резервной копии действует и на данные источников.
- Смена IP не переписывает адреса и учётные данные сохранённых подключений. Открывается выбранная запись с её адресом и датой. Статус «Обновлено» не выдаётся за доказательство, что устройство сейчас в сети.

## Проверки

Автоматические сценарии на Android API 28 и 35: смена IP и перезапуск, разные сети и сервисы, дубли UUID, повторное использование IP, ручное объединение/разделение и повторный поиск, сохранённые подключения без копирования паролей, целостность и восстановление копии, сохранение после очистки исходной истории, миграция SQLite v2 и прежних названий, строгий разбор UUID.

Выпуск: `testReleaseUnitTest lintRelease assembleRelease` локально и в GitHub Actions. Физическая проверка на телефоне остаётся отдельной: открытие/прокрутка карточек, объединение и разделение, поиск после DHCP, переключение Wi-Fi/LTE/VPN, восстановление копии. В этой сессии телефон не подключён.
