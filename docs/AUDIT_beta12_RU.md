# Аудит SiteScope Pro (beta12) и план исправлений

Дата: 2026-11-13. Ветка `redesign`. Метод: статический разбор кода и документации, CI (тесты + Lint). Запуск на физическом устройстве в этом аудите **не выполнялся**.

## 0. Правки Codex (beta13–beta23): появились в `redesign` во время аудита

Первый проход (до обновления ветки) этих коммитов не видел; затем они были запушены и разобраны. Объём: ~100 файлов — карточки устройств и история измерений, отпечатки HTTP/TLS/ONVIF, отчёты CSV/JSON/HTML, чтение DHCP/ARP с **собственных** роутеров RouterOS/OpenWrt по API, сравнение снимков, смена имени роутера с журналом отката, внешние TCP-измерения, перемотка ТВ, ONVIF/RTSP-сессии, регулировка 2–250 потоков и «IPTV без лимита хостов».

Вывод по соответствию заявленной цели: это **не** перенос RouterScan (нет подбора паролей, нет эксплуатации чужих устройств, нет сбора учётных данных). Все операции с роутером идут по учётным данным владельца, фиксированным набором вызовов; логин/пароль лежат в `SecureStore` и привязаны к адресу и типу адаптера; запись имени роутера защищена предпросмотром (срок 120 с), проверкой «значение не изменилось», журналом до записи и проверкой результата; отчёты вычищают пароли/токены (`ReportText`). Это верное направление, совпадающее с `docs/08_AUTHORIZED_SCANNER_RU.md`. Функции RouterScan по подбору паролей и извлечению учётных данных чужих роутеров не добавлялись и не должны добавляться.

## 2. Что добавлено в beta25

- **Скорость как в Ookla Speedtest** (`net/SpeedEngine.kt`, `SpeedScreen.kt`): спидометр с нелинейной шкалой, задержка/джиттер/потери, задержка под нагрузкой, скачивание и отдача в несколько потоков с «живой» скоростью, пик, серверы (Cloudflare, Tele2, Hetzner, OVH, свой), настройки (что измерять, единицы Мбит/с · МБ/с · кбит/с, длительность, потоки, число пингов, лимит трафика), история и «поделиться». Старая проверка «скачать/отправить файл» удалена.
- **Поиск потоков по маске** (`tv/MaskSearch.kt`, `MaskSearchScreen.kt`): `%d`, `%d{a-b}`, `%03d`, `(a|b|c)`, `(.*)`, `channel_name`, `xxx.xxx.xxx.xxx`, `yyyyy`; перебор с лимитом, параллельностью, быстрой отсечкой мёртвых host:port; http/https — полная проверка потока, rtsp — DESCRIBE, rtmp/mms — проверка порта. Окно вверху: квадрат с кадром из потока (или логотип из ваших каналов) и распознанное название. Название берётся из служебных таблиц потока (SDT), затем читается с эмблемы (OCR), затем из маски; известные каналы приводятся к виду «1+1», «Интер», «НТВ», «РЕН ТВ». Вход: «Ещё → Поиск ТВ по маске», раздел «ТВ в локальной сети» и «Добавить плейлист».
- Тесты: `MaskSearchTest` (перебор, диапазоны, нули, альтернативы, `(.*)`, названия, IP/порты, распознавание).

## 3. Ограничения (честно)

- Название по эмблеме читает Tesseract (язык rus: кириллица, латиница, цифры, `+`; данные `rus.traineddata` ≈3,9 МБ в assets, библиотека Tesseract4Android 4.9.0 с JitPack, только arm64). Читаются четыре угла до трёх кадров, снятых в случайные моменты; известные каналы принимаются с одной опечаткой, произвольный текст — только при двух совпадающих уверенных чтениях. Если эмблема не видна — «Нет названия». Украинские буквы і/ї/є модель rus не знает (читаются как и/и/е); добавить `ukr` — ещё ≈3,8 МБ. Точность на реальных потоках не измерена (устройства не было): кадр с титрами или без эмблемы названия не даст.
- `udp://` и `rtp://` без подписки на группу проверить нельзя — такие комбинации пропускаются.
- Серверы Tele2/Hetzner/OVH — публичные тестовые файлы; их доступность не гарантируется (Cloudflare — основной).
- Сборка и тесты проверяются только в CI; устройства для проверки не было.
