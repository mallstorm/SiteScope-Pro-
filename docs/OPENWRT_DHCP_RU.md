# Этап 9 — DHCP OpenWrt через LuCI/rpcd (beta22)

«Моя сеть → Роутеры → OpenWrt» теперь сначала вызывает через /ubus фиксированный метод luci-rpc.getDHCPLeases с family=4. Возвращаемый dhcp_leases содержит IPv4-аренды; hostname, ipaddr и mac проецируются в имя, адрес и MAC. Прочие поля, IPv6-аренды и сырые ответы не копируются. LuCI читает данные обслуживающих DHCP-компонентов, включая dnsmasq; название метода не доказывает, какой именно демон создал конкретную запись. Поле lease_source обозначает API-метод, а не угаданного производителя или состояние клиента.

Нужны rpcd, uhttpd-mod-ubus, rpcd-mod-luci и разрешение чтения ubus luci-rpc/getDHCPLeases для пользователя владельца. Существующие чтения system/board, system/info, network.interface/dump и session login/destroy сохраняются. Новых операций записи, доступа к файлам роутера или запуска команд нет. Приложение не устанавливает пакеты и не меняет ACL автоматически.

При отсутствии метода/объекта или отказе ACL (ubus 3/4/6, JSON-RPC -32002) используется прежний dhcp.ipv4leases odhcpd. Если он доступен, снимок содержит его источник; отказ основного способа не делает успешное резервное чтение частичным. Корректный пустой dhcp_leases — полноценный ответ: резервный метод не вызывается и записи из разных методов не смешиваются. Если оба способа недоступны, снимок помечается частичным и содержит пояснение об отсутствии метода или правах. Это не утверждение об отсутствии клиентов.

Неверная структура ответа помечает DHCP как неопределённый раздел; переключения на другой способ после ошибки структуры нет. Сбой HTTP-авторизации, TLS, сети, таймаут или отмена не вызывают резервный вход/обход. Данные входа и ubus-токен не включаются в ошибки и снимки. Сессия завершается прежним механизмом logout/TTL. Сохраняются ограничения 1 МиБ на ответ, 512 КиБ нормализованных строк и общий временной бюджет.

В снимке показывается dhcpSource; у каждой аренды есть lease_source. Это поле доступно для выбора в CSV/JSON/HTML. При подтверждении связи DHCP с карточкой метод сохраняется в её источнике. Смена метода между двумя снимками (включая переход с прежнего снимка без сведений об источнике) делает определение добавленных/исчезнувших строк ненадёжным: такие различия скрываются с пояснением. Изменения известных полей совпавшего MAC продолжают показываться. Из предосторожности при этом скрываются также добавления/удаления интерфейсов; это не измерение их доступности.

Резервная копия v13 сохраняет новые поля; SQLite остаётся v7 — новая таблица не нужна. Копии прежних версий поддерживаются. Неизвестное происхождение старой аренды не заполняется догадкой. Учётные данные остаются только в защищённом хранилище Android.

## Проверки

Локальные HTTP-фикстуры: LuCI family=4, пустой ответ без fallback, отсутствие метода, отказ ACL обоих форматов, odhcpd fallback без дублирования, обе операции недоступны, неверный формат, HTTP 401 и завершение сессии. Проверки проекции полей, прежнего/нового формата odhcpd, смены источника, резервного восстановления и CSV/JSON/HTML выполняются на Android SDK 28/35 через Robolectric.

Физические роутеры/телефон в этой сессии не подключены. Для приёмки нужны OpenWrt с dnsmasq/rpcd-mod-luci, затем odhcpd-only, ограниченный ACL и сравнение с таблицей аренды в LuCI. Проверить пустые списки, смену прав, перенос источника в ручную связь и открытие трёх форматов отчёта.

## Источники контрактов

- [Исходники rpcd-mod-luci](https://github.com/openwrt/luci/blob/master/libs/rpcd-mod-luci/src/luci.c): объект luci-rpc, метод getDHCPLeases, family=4, dhcp_leases и поля строк.
- [ACL LuCI](https://github.com/openwrt/luci/blob/master/modules/luci-mod-status/root/usr/share/rpcd/acl.d/luci-mod-status.json): права чтения getDHCPLeases.

Далее остаются этап 10 — настройки своих роутеров с предварительным просмотром, подтверждением и откатом — и этап 11, физическая приёмка/подготовка стабильного выпуска. Поддерживаемые операции изменения настроек потребуют отдельного определения точных параметров и прошивок перед реализацией.
