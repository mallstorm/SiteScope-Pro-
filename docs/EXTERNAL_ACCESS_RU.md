# Внешняя доступность собственных сервисов — этап 6, beta19

## Экран

«Моя сеть → Доступ извне». Укажите собственный IP или домен без URL/паролей, выберите TCP-порты и подтвердите право на проверку. Цель можно сохранить. Проверка не выполняет вход в сервис и не отправляет запросы прикладных протоколов: измеряется установление TCP-соединения.

Режимы:

- **Мобильная сеть** — приложение запрашивает cellular Network, даже если по умолчанию используется Wi-Fi. Мобильные данные должны быть включены. Если сеть не появилась за 20 секунд, запуск завершается ошибкой; переключения на Wi-Fi нет.
- **Текущая сеть** — для сравнения с локальной точкой, включая Wi-Fi/Ethernet/VPN. DNS и сокеты привязаны к выбранному Network на всё измерение; смена системной сети по умолчанию не меняет эту привязку.

Общие настройки сетевых проверок: 2–250 параллельных работников и задержка 0–5000 мс между стартами. Параметры фиксируются при запуске. Для этого экрана предусмотрена одна цель, до 64 выбранных портов и до 4096 сочетаний DNS-адрес/порт; большие задания отклоняются явно. Эти пределы не меняют отсутствие лимита адресов IPTV и существующие пределы общего сканера.

Проверяются все полученные DNS-адреса, помещающиеся в допустимый объём. Результат содержит фактический числовой адрес, порт, время и задержку: TCP доступен, соединение отклонено, таймаут, ошибка DNS или сети. Отказ и таймаут не объявляются выключенным устройством.

## Что подтверждает измерение

Положительная внешняя отметка выдаётся конкретному публичному адресу и порту только при успешном TCP-connect через однозначно определённую мобильную сеть. Проверяется выбранный Network до и после задания; активный VPN, смешанные/неизвестные транспорты, отмена, потеря сети, ошибка или неполное выполнение не дают такой отметки.

Открытый порт через Wi-Fi может объясняться NAT loopback или локальным маршрутом. Он не считается доказательством доступа из интернета. Частные, loopback, link-local, CGNAT, multicast и известные служебные/документационные адреса также не получают отметку публичной доступности. Домены оцениваются по фактически разрешённым адресам, а не по имени.

Это точечное наблюдение TCP с выбранной сети в указанное время. Оно не доказывает работоспособность приложения, успешную авторизацию, отсутствие уязвимости или доступность из всех сетей. Прозрачные прокси/особые настройки оператора могут влиять на результат. IP телефона с внешнего сервера не запрашивается; сторонний измерительный сервер этим выпуском не развёртывается. Реализована мобильная точка, предусмотренная этапом 6; интеграция с внешним агентом может быть добавлена отдельно.

## Отмена и хранение

«Отменить», уход со вкладки и сворачивание приложения отменяют задачу, закрывают зарегистрированные TCP-сокеты и освобождают cellular NetworkCallback. Системное разрешение DNS на некоторых версиях Android может завершиться позже; мгновенное прерывание системного вызова не гарантируется. Частичные данные сохраняются с соответствующей отметкой.

Цели и последние 100 измерений хранятся отдельно от LAN-карточек. Удаление цели не удаляет историю; история очищается отдельной командой. Данные не содержат URL с учётными данными, секретов или ответов сервисов. SQLite v5 добавляет две таблицы без удаления прежних данных. Копия v10 переносит цели и измерения; данные проверяются до замены, ошибка откатывает восстановление. Прежние копии без этого раздела поддерживаются.

## Проверки

Автоматические сценарии: различение Wi-Fi/cellular/VPN/неизвестной точки, частные и публичные адреса, отказ от диапазонов/URL, сохранение и предел истории, миграция SQLite v4, восстановление копии/откат повреждённого источника, реальный TCP на loopback без отправки прикладных данных, выдача/освобождение мобильной заявки и отмена без fallback.

Для физической проверки нужен собственный опубликованный сервис и телефон: сравнить Wi-Fi и мобильную сеть, проверить открытый/закрытый порт, отключение данных, VPN, DNS с несколькими адресами, отмену и восстановление копии. В этой сессии реальная мобильная сеть и чужие публичные адреса не проверялись.
