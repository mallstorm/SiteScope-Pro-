# Shodan и мониторинг доступности в SiteScope Pro

## Как устроен Shodan

Shodan собирает наблюдения о публично доступных сетевых сервисах. Его базовая запись — баннер сервиса. В записи могут быть IP, порт, транспорт, время наблюдения, ответ сервиса и нормализованные свойства протокола. Один IP может иметь несколько баннеров разных сервисов. Поэтому результаты запроса по сервисам и количество уникальных устройств могут отличаться. [Модель данных и поиск Shodan](https://help.shodan.io/the-basics/search-query-fundamentals)

Поиск работает по собранному индексу. Строка запроса фильтрует записи, карточка IP группирует наблюдения по адресу, а фасеты подсчитывают совпадения по полям. REST API обслуживает выборки и сводки, отдельный поток отдаёт новые записи по мере сбора. Запуск поиска и запуск измерения — разные операции. [REST API](https://developer.shodan.io/api) · [REST и Streaming API](https://developer.shodan.io/api/introduction)

Окно свежести зависит от экрана. По документации основной поиск показывает последнее наблюдение пары IP и порта за 30 дней. История IP покрывает до 90 дней и ограничена 1000 баннерами, а панель Monitor смотрит на последние 48 часов. Например, дата баннера в поиске описывает момент измерения. [Окна данных](https://help.shodan.io/mastery/data_timeline)

Monitor ведёт группы активов, которые можно задать сетью, доменом или поисковым запросом. Правила применяются к новым наблюдениям. Например, правило нового сервиса срабатывает при появлении ранее не встречавшегося порта. Журнал включает уведомления и изменения состава динамической группы. Сам журнал хранит две недели событий по документации Shodan. [Правила Monitor](https://help.shodan.io/command-line-interface/4-network-monitoring) · [Журнал событий](https://help.shodan.io/shodan-monitor/events-log)

## Как это встроено в SiteScope Pro

| Возможность | Где и как работает |
| --- | --- |
| Активы | «Моя сеть → Ещё → Доступ извне → Проверка». Выбирается сохранённый IP или домен и список своих TCP-портов. |
| Наблюдение | «Доступ извне → Наблюдение → Последние замеры». Для адреса и порта показываются результат, точка и время. |
| Поиск и сводка | Поле поиска подбирает результаты по названию цели, домену, измеренному IP, порту и подписи точки. Фильтры `port:`, `ip:` и `host:` можно сочетать. Число строк обновляется по запросу. |
| Журнал | «Наблюдение → Изменения» показывает переходы между принятым и отклонённым TCP-соединением. У записи есть переход к исходному измерению. |
| История | Используются сохранённые замеры «Доступа извне», включая замеры предыдущих версий. Окно охватывает последние 100 измерений. |

Первый однозначный замер становится исходным. Сравнение идёт внутри одной цели, фактического IP, порта, типа точки измерения и признака внешнего измерения. Когда домен начинает отвечать по другому адресу, у нового адреса появляется своё исходное состояние. Изменение списка проверяемых портов само по себе событий не создаёт.

Таймаут и сетевая ошибка отображаются как неопределённое состояние. Они сохраняют предыдущий однозначный замер для сравнения при следующем ответе. Отменённые и неполные проверки исключаются. Успешное TCP-соединение описывает доступность с выбранной сети на момент замера.

Наблюдение опирается на существующий ручной замер и автоматически пересчитывает журнал после сохранения результата. Глобальный индекс, фоновый сетевой сбор и API Shodan находятся вне этой реализации.
