# Спецификация 36 — архитектурная стабилизация

## Правила
1. SEO, IP и IPTV не смешиваются.
2. В IP Engineering каждая задача имеет собственный экран.
3. Большие коллекции не хранятся одним JSON в SharedPreferences.
4. Длительные операции сохраняют checkpoint отдельно от результатов.
5. Новая локальная база не заменяет рабочую до полной проверки.
6. Большие списки обязаны быть виртуализированными.
7. Наличие класса в APK не является доказательством совместимости протокола.

## IP Engineering Hub
```
IP Engineering

```

## SQLite
`sitescope_app.db` является источником истины для пользовательских проектов и результатов. SharedPreferences используются только для небольших настроек и checkpoint состояния.

## DB-IP lifecycle
```
скачивание → staging import → контрольная проверка → транзакционная замена → ready
                         ↘ ошибка → удалить staging → сохранить старую базу
```

## Readiness
- Stable — базовый сценарий подтверждён тестовым harness и используется как основной.
- Beta — компонент реализован, но требует проверки с конкретным оборудованием.
- External — запуск делегируется совместимому приложению.
