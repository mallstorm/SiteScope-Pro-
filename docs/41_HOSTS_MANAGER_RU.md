# Hosts Manager — техническая спецификация

## Назначение

Hosts Manager управляет локальными соответствиями `IP → hostname` на Android. Инструмент расположен в:

`Главная → IP Engineering → Hosts Manager`

Он предназначен для разработки, локального тестирования, перенаправления собственных доменов, блокировки нежелательных доменов и обслуживания разрешённых пользователем устройств.

## Формат записей

Поддерживается стандартный формат hosts:

```text
128.0.3.22 sige.ru
192.168.1.10 router.home router
0.0.0.0 ads.example.org # локальная блокировка
2001:db8::25 api.example.test
```

Строка `128.00.03.22 sige.ru` принимается с предупреждением и сохраняется в каноническом виде:

```text
128.0.3.22 sige.ru
```

Поддерживаются:
- IPv4 и IPv6;
- несколько имён через пробел;
- комментарий после `#`;
- временное отключение записи;
- IDN-домены с приведением к ASCII/punycode.

Не поддерживаются:
- URL со схемой и путём;
- wildcard `*.example.org`;
- порт в имени;
- некорректные IP;
- пустые или недопустимые DNS-метки.

## Модель данных

SQLite содержит:

- `hosts_profiles` — именованные профили и активный профиль;
- `hosts_entries` — записи, порядок, активность и источник;
- `hosts_backups` — метаданные локальных резервных копий;
- `hosts_apply_events` — журнал применения и хеши до/после.

Профиль можно создать, переименовать, активировать, дублировать и удалить. Основной профиль удалить нельзя.

## Управляемый блок

SiteScope Pro изменяет только собственный блок:

```text
# BEGIN SITESCOPE PRO MANAGED HOSTS
...
# END SITESCOPE PRO MANAGED HOSTS
```

Строки производителя, прошивки и других инструментов вне блока сохраняются. При повторном применении старый управляемый блок заменяется атомарно, а не добавляется повторно.

## Валидация

Перед применением выполняются:

1. синтаксический разбор;
2. нормализация адресов и hostnames;
3. обнаружение повторяющихся строк;
4. предупреждение о нескольких адресах для одного hostname;
5. проверка пустых и недопустимых значений;
6. построение итогового кандидата;
7. расчёт SHA-256 текущего и нового файла.

Ошибки блокируют применение. Предупреждения показываются пользователю, но не всегда запрещают сохранение.

## Режимы применения

### 1. Magisk systemless

При наличии root и Magisk создаётся модуль:

```text
/data/adb/modules/sitescope_hosts/
├── module.prop
└── system/etc/hosts
```

Исходный `/system` напрямую не перезаписывается. После установки выполняется попытка активировать bind-mount сразу. На некоторых прошивках потребуется перезагрузка.

### 2. Временный root bind-mount

Если root доступен без Magisk, кандидат хранится в приватном каталоге приложения и накладывается на системный hosts через bind-mount. Такой режим обычно действует до перезагрузки.

### 3. Локальный DNS-VPN без root

VpnService создаёт локальный DNS-адрес `10.203.0.1`, перехватывает системные A/AAAA-запросы и:

- отвечает локальным адресом при совпадении активной записи;
- перенаправляет остальные запросы DNS-серверам базовой сети;
- не маршрутизирует весь пользовательский трафик через удалённый сервер.

Ограничения режима:
- одновременно в Android может работать только один VPN;
- приложения с собственным DoH/DoT или прямым IP могут не использовать правила;
- изменение профиля вызывает reload службы;
- пользователь может остановить службу системным интерфейсом Android.

## Резервные копии и откат

Перед root-применением сохраняются:

- содержимое текущего hosts;
- время;
- режим;
- путь источника;
- размер;
- SHA-256.

Из экрана резервных копий доступны просмотр, экспорт и восстановление. Перед восстановлением текущий файл также резервируется.

## Импорт и экспорт

Через системный файловый интерфейс Android поддерживаются:

- импорт текстового hosts до 4 МБ;
- экспорт активного кандидата;
- экспорт отдельной резервной копии.

## Границы безопасности

- Нет загрузки чужих списков без явного действия пользователя.
- Нет автоматического изменения системного файла при запуске.
- Root-команды запускаются только после подтверждения.
- Системный раздел не перемонтируется для прямой записи.
- Применение блокируется при ошибках парсинга.
- Работа предназначена для собственных устройств и разрешённых ресурсов.
