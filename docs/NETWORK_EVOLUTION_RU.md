# Развитие сетевой диагностики SiteScope Pro

План от 13 ноября 2026 года. Основан на текущем коде beta13 и исследовании архитектуры Router Scan. Реализация самостоятельная, с Android API и существующими движками SiteScope.

Порядок работы: завершить один этап, проверить его, собрать APK через Actions, выдать результат и предложить следующий этап. Календарные сроки не назначаются до уточнения объёма конкретного этапа.

## Этап 1: договорённости интерфейса

- Число потоков — максимум одновременных проверок, задержка — интервал между стартами новых проверок во всём задании. Это независимые параметры.
- Ползунки доступны в «Моя сеть → Сканер», «ТВ → Локальная сеть» и настройках. Они задают параметры новых запусков; работающий сканер сохраняет выбранный при запуске набор.
- По умолчанию используются прежние настройки общего сканера. Если пользователь сохранял выбор в IPTV, при первом обновлении он становится общим набором; повторной миграции нет.
- Пауза останавливает выдачу новых разрешений на старт. Уже начатые проверки могут завершиться.
- Остановка закрывает зарегистрированные TCP/TLS-сокеты общего сканера. Системное DNS-разрешение не гарантирует мгновенную прерываемость на каждой версии Android.
- Пул и число удерживаемых заданий ограничены выбранной параллельностью. Ограничения объёма общего сканера и отсутствие лимита адресов IPTV остаются отдельными правилами существующих движков.

## Проверки и выпуск этапа

Нужны проверки миграции настроек, границ 2/250 и 0/5000, общего темпа работников, паузы, отмены ожидания и checkpoint. Существующие интеграционные проверки IPTV должны сохранить параллельность и интервал. Локально и в Actions выполняются testReleaseUnitTest, lintRelease, assembleRelease; APK и отчёты относятся к одному commit SHA.

Физическая проверка на телефоне отдельно покрывает ползунки, фон/возврат, Wi-Fi/LTE/VPN и остановку. Успех JVM-тестов не заменяет эту проверку.
