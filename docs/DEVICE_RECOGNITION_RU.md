# Распознавание оборудования — этап 2, beta15

Результат оборудования отделён от результата определения протокола. HTTP или TLS могут быть уверенно распознаны, даже если производитель и модель неизвестны. Признаки относятся к ответившему сервису; обратный прокси может представлять несколько устройств.

## Что появилось

- Производитель, семейство, модель, тип, отдельная уверенность и список подтверждающих наблюдений.
- Каждое наблюдение хранит поле, значение, источник и уверенность. Сохраняются время получения и версия правил.
- Значок информации у порта открывает сведения о распознавании как в текущем сканировании, так и в истории. Открытие самого сервиса осталось отдельным действием.
- Сведения передаются в существующую панель сервиса. История сканирования, checkpoint и снимки обнаружения сохраняют новые поля без изменения схемы SQLite, поскольку используют версионируемое JSON-содержимое.
- ONVIF-клиент использует структурированный ответ GetDeviceInformation для производителя и модели; hardware scope из WS-Discovery показывается отдельно и не выдаётся за модель.
- Из старых SSDP-снимков общий текст Linux/UPnP не переносится в производителя. Старый ONVIF hardware переносится в наблюдение; дата такого наблюдения не подменяется текущей.

Это ограниченный каталог признаков, а не обещание поддержки любой прошивки или каждой модели. Модель берётся из явного текста ответа; по номеру порта, одному производителю, версии ПО или общему названию веб-сервера она не подставляется. Название бренда в произвольной статье/официальном сайте без признаков интерфейса не считается достаточным заголовком оборудования.

Каталог реализован в DeviceFingerprintEngine.java. Обезличенные синтетические примеры типовой формы находятся в app/src/test/resources/fingerprints/http-identities.tsv. Они проверяют поведение правил, но не заменяют испытание на реальных прошивках.

## Источники и уверенность

| Источник | Использование | Уверенность |
|---|---|---|
| HTTP Server / WWW-Authenticate realm | Характерные маркеры; модель только из явного подходящего текста realm | Средняя |
| HTML title | Семейство/модель из заголовка интерфейса; текст статьи, комментарии и скрипты не анализируются как заголовок | Средняя |
| TLS subject, атрибут O | Только ограниченный список точных организаций; не CN, не издатель сертификата и не модель | Низкая; сертификат отдельно не проверялся |
| ONVIF GetDeviceInformation | Поля Manufacturer и Model документированного SOAP-ответа | Высокая для сообщения устройства, не удостоверение подлинности |
| ONVIF WS-Discovery hardware | Отдельный аппаратный идентификатор | Низкая для hardware; модель остаётся неизвестной |

При несовпадающих производителях или моделях выводится конфликт. Автоматический выбор одного из противоречащих вариантов не выполняется; наблюдения сохраняются для просмотра.

## Получение страницы и ограничения

Для уже проверяемого HTTP/HTTPS-сервиса выполняется GET корня `/` без учётных данных, cookies, исполнения JavaScript и переходов по редиректам. Общий объём ответа ограничен 24 КиБ, заголовков — 8 КиБ; применяется ограничение времени чтения. Разбор поддерживает ограниченный chunked-ответ и charset, запрашивает identity encoding. Если сервер всё же сжимает тело, модель из него не извлекается. Тела страниц целиком не сохраняются: в наблюдениях остаются совпавшие маркеры и значения.

Из ответов перенаправления/ошибки HTML title не используется; заголовок авторизации может дать отдельный признак. Если интерфейс доступен только после перенаправления или работает полностью через JavaScript, сведений для модели может не хватить. Неполный/неоднозначный заголовок не восполняется догадкой.

Диагностическое TLS-рукопожатие сканера читает сертификат без отправки секретов. Оно не означает доверие цепочке/имени; интерфейс показывает «Доверие сертификату TLS: не проверялось». Существующие авторизованные клиенты сохраняют свои отдельные проверки TLS.

## Проверки

Положительные примеры восьми производителей; отрицательные примеры общих веб-серверов и рекламных заголовков; конфликт производителей/моделей; TLS O/CN; частичный HTTP-ответ; chunked, редиректы и сжатие; структурированный ONVIF, чужие пространства имён, SOAP Fault и запрет DTD/ENTITY; сохранение истории/intent и чтение прежних снимков. Полный сканер проверяется на локальном сервере с произвольным портом.

Физические устройства в этой сессии не проверялись. Объединение сведений между IP, портами и сохранёнными подключениями относится к следующему этапу 3; сейчас результат распознавания привязан к конкретному наблюдению.
